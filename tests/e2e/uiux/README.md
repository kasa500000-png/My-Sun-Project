# UI·UX E2E 실행 계약

현재 저장소에는 Playwright 의존성과 테스트 계정이 없으므로 실행되지 않는 가짜 spec을 추가하지 않는다. 브라우저 환경이 연결되면 다음 순서로 구축한다.

## 공개 화면 우선

1. `/login` 로그인·회원가입 탭과 필드 오류
2. `/offline` 온라인·오프라인 전환
3. 존재하지 않는 경로의 404
4. 앱 오류 boundary의 재시도

## 인증 후 핵심 흐름

1. 홈 → 운동 기록
2. 운동 검색·루틴·부위 필터
3. 운동 입력 → 저장 → 일지 확인
4. 분석 기간 변경과 데이터 부족 상태
5. 식단 직접 입력·AI 실패 fallback
6. 내 정보 저장·취소·로그아웃

## 선택자 원칙

- `getByRole`, accessible name, label 우선
- 동적 문구가 불안정할 때만 `data-testid`
- CSS 클래스와 DOM 순서에 의존하지 않음
- 운영 계정과 실결제·삭제 동작 사용 금지

## 필수 환경

- `DEPLOYED_APP_URL` 또는 로컬 `BASE_URL`
- 전용 Supabase 테스트 프로젝트
- 테스트 계정 이메일·비밀번호
- 비식별 시드 운동·식단 데이터
- Playwright 버전과 브라우저 설치를 lockfile에 고정
