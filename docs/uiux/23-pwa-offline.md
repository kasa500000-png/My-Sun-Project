# PWA·오프라인·연결 복구

## 발견한 운영 데이터 위험

기존 서비스 워커는 성공한 모든 동일 출처 네비게이션 응답을 캐시에 저장했다. 인증 후 `/` 화면이 서버에서 개인 운동·식단 데이터를 포함할 경우, 오래된 개인 HTML이 기기 캐시에 남을 가능성이 있었다.

## 적용한 보호 조치

- 서비스 워커 캐시 버전을 v5로 갱신
- 공개 네비게이션 `/login`, `/offline`만 HTML 캐시 허용
- 인증 후 루트와 기타 네비게이션 응답은 네트워크로만 처리
- API와 인증 콜백은 기존처럼 캐시 제외
- 정적 아이콘·이미지·manifest만 stale-while-revalidate 성격으로 유지
- 응답이 성공한 경우에만 정적 자산 캐시 갱신
- 서비스 워커 등록에 `updateViaCache: none` 적용
- 온라인 복구와 앱 재표시 시 업데이트 확인

## 오프라인 화면 UX

- 사용자가 현재 연결 상태를 실시간으로 확인
- 연결 복구 시 CTA가 ‘앱으로 돌아가기’로 변경
- 재시도 실패 시 Wi-Fi·모바일 데이터 확인 안내
- 저장 전 입력이 서버에 전송되지 않았음을 명시
- 인증 후 개인 화면을 오프라인 캐시에 저장하지 않는다는 개인정보 안내

## 보존한 동작

- 오프라인 fallback
- 오래된 캐시 정리
- 서비스 워커 즉시 활성화와 client claim
- 아이콘·브랜드 이미지 오프라인 제공

## 검증 필요

- 설치된 PWA에서 v4→v5 캐시 정리
- 오프라인 `/` 진입 시 개인 화면 대신 `/offline` 표시
- 온라인 전환 후 버튼과 서비스 워커 업데이트
- Safari·Chrome PWA 설치와 업데이트
