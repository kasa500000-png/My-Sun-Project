# 로그인·회원가입 UX 개선

## 사용자 문제

인증 실패 시 사용자는 이메일 형식, 비밀번호 오타, 네트워크 오류 중 무엇이 문제인지 빠르게 구분하기 어려웠다. 모바일에서 비밀번호를 확인할 방법도 없었다.

## 적용한 개선

### 정보 구조

- 제품 가치와 주요 기능을 히어로에 짧게 설명
- 폼 제목을 ‘다시 만나 반가워요’와 ‘기록을 시작해 볼까요?’로 맥락화
- 이메일·비밀번호 입력 목적과 가입 후 자동 로그인 동작 설명

### 입력 편의성

- ‘아이디’를 ‘이메일’로 변경
- `name`, `id`, `inputMode`, `autoCapitalize`, `spellCheck`, `autoComplete` 정비
- 비밀번호 보기·숨기기 토글 추가
- 제출 중 모든 입력·모드 전환·토글 비활성화
- 이메일 앞뒤 공백 정규화

### 오류 복구와 접근성

- 로컬 검증 오류를 필드 가까이에 표시
- `aria-invalid`와 `aria-describedby` 연결
- 필드 오류는 assertive alert, 전역 안내는 info/danger live region으로 분리
- 오류가 난 필드를 수정하면 해당 오류를 지움
- 로그인 서버·네트워크 오류에도 입력값 유지
- 기존 안전한 next 경로 검증과 Supabase 인증 흐름 유지

## 변경하지 않은 기능

- 별도 비밀번호 재설정 기능은 저장소에 존재하지 않아 임의 추가하지 않았다.
- 소셜 로그인과 이메일 인증 흐름을 새로 만들지 않았다.
- Supabase 정책, API 경로, 회원 데이터 구조를 변경하지 않았다.

## 실화면 검증 필요

- iOS·Android 자동완성과 비밀번호 관리자
- 소프트 키보드가 제출 CTA를 가리지 않는지
- 잘못된 이메일, 짧은 비밀번호, 불일치, 401, 타임아웃
- 이미 로그인된 세션의 자동 이동
