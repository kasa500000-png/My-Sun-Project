# 빈 상태·오류·오프라인 상태

## 공통 상태 구조

1. 상태 종류
2. 사용자가 이해할 수 있는 제목
3. 발생한 일과 데이터 영향
4. 한 개의 기본 복구 행동
5. 필요할 때만 보조 행동
6. 오류 식별자 또는 개인정보 안내

## 적용 화면

### 앱 오류

- 네트워크 또는 데이터 처리 문제라고 설명
- 저장 직후 오류라면 중복 저장 전에 홈·일지 확인 안내
- 같은 화면 재시도와 홈 이동 제공
- Next.js 오류 digest가 있을 때만 기술 식별자 표시

### 404

- 주소 변경 또는 사용할 수 없는 화면이라고 설명
- 저장 데이터에는 영향이 없다고 명시
- 홈 이동과 로그인 화면 이동 제공

### 오프라인

- Stage 23의 실시간 연결 상태와 재시도 제공
- 저장 전 입력은 서버에 전송되지 않았음을 설명
- 인증 후 개인 HTML을 캐시하지 않는 정책 안내

## 기존 화면 내부 빈 상태

다음 빈 상태는 도메인 문맥과 CTA를 이미 제공하므로 유지한다.

- 첫 운동 기록 없음
- 선택 기간 운동 기록 없음
- 운동 검색 결과 없음
- 분석할 기록 없음
- 식단 기록 없음

향후 공통 `EmptyState` 컴포넌트 분리는 `FitLogApp.tsx` 표현 계층 분해와 함께 수행한다.

## 오류 문구 원칙

- 기술 예외 문자열을 사용자에게 그대로 표시하지 않는다.
- 저장 성공·실패 여부를 추측하지 않는다.
- 재시도로 중복 생성될 수 있으면 먼저 확인할 위치를 안내한다.
- 데이터가 안전한지 확인 가능한 범위만 말한다.
