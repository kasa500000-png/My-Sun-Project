# 레이아웃·반응형·Safe Area 기준

## 지원 매트릭스

| 분류 | 뷰포트 | 핵심 검증 |
|---|---|---|
| 작은 모바일 | 360×800 | 숫자 입력, 바텀시트 footer, 긴 한국어 |
| 표준 모바일 | 390×844 | 핵심 사용자 여정 기준 |
| 큰 모바일 | 412×915 | 카드 밀도, 하단 탭 |
| 태블릿 | 768×1024 | 콘텐츠 폭, 모달 중앙 정렬 |
| 데스크톱 | 1280×800 | 과도한 폭과 빈 공간 |
| 큰 데스크톱 | 1440×900 | 대시보드 최대 폭 |

## 구현한 전역 보호 장치

- `html`, `body`, `.mysun-page`의 가로 넘침 차단
- 화면 좌우 Safe Area 반영
- 모바일 하단 탭과 바텀시트 footer의 하단 Safe Area 반영
- 입력 포커스 시 고정 헤더 아래에 보이도록 scroll margin 설정
- iOS 입력 확대를 막기 위해 모바일 입력 글자 16px 유지
- 389px 이하에서 sheet footer를 1열 CTA로 전환
- 태블릿 이상에서 바텀시트를 중앙 모달 형태로 제한
- 짧은 가로 화면에서 바텀시트 최대 높이 재계산
- `svh`와 지원 시 `dvh`를 함께 사용

## 회귀 주의

- `overflow-x: clip`은 숨겨진 가로 스크롤을 해결하는 대신 원인을 가릴 수 있으므로 실제 브라우저에서 원인 요소를 별도 확인한다.
- 하단 메뉴는 `aria-label="하단 메뉴"` 계약에 의존한다.
- 360px 영양 입력 2열 전환은 실제 식단 컴포넌트 변경 단계에서 적용해야 한다.

## 실화면 체크리스트

- [ ] 키보드가 운동·식단 저장 CTA를 가리지 않음
- [ ] 하단 탭이 마지막 카드와 겹치지 않음
- [ ] 태블릿에서 카드가 지나치게 넓어지지 않음
- [ ] 데스크톱에서 읽기 줄 길이가 과도하지 않음
- [ ] 큰 글자에서 버튼 라벨이 잘리지 않음
- [ ] 가로 모드에서 모달 header/footer에 접근 가능
