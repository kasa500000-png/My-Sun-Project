# 핵심 사용자 여정과 마찰 분석

## 분석 방식

현재 단계의 탭 수와 마찰은 소스 구조 기준 예상값이다. 실제 브라우저 실행 시 클릭 수, 포커스 이동, 스크롤 거리와 뒤로 가기 동작을 다시 계측한다.

## J01 첫 진입 → 로그인 → 홈

**성공 조건:** 사용자가 계정 입력 방식과 제출 상태를 이해하고, 오류 발생 시 입력값을 잃지 않은 채 복구한다.

1. `/login` 진입
2. 이메일 입력
3. 비밀번호 입력
4. 로그인 제출
5. 세션 생성 후 안전한 `next` 또는 홈으로 이동

**현재 마찰**

- 이메일 필드가 ‘아이디’로 표시돼 입력 형식을 추측해야 한다.
- 비밀번호 표시 기능이 없어 모바일 오타를 확인하기 어렵다.
- 오류와 일반 안내가 같은 시각 톤으로 표시된다.
- 로그인 오류가 해당 필드와 직접 연결되지 않는다.

**개선 성공 지표**

- 필드 목적과 자동완성 명확화
- 제출 중 중복 클릭 불가
- 오류가 `role=alert`와 설명 연결로 즉시 인식
- 비밀번호를 안전하게 표시·숨김 가능

## J02 홈 → 추천 확인 → 운동 기록 저장

**성공 조건:** 오늘 할 행동을 이해하고 운동을 선택해 최소 입력으로 저장한다.

1. 홈에서 주간 목표와 오늘 추천 확인
2. `운동 기록하기` 또는 상단 `기록` 선택
3. 날짜·운동 시간 확인
4. 운동 검색 또는 루틴·부위 필터
5. 운동 행 선택
6. 세트·중량·횟수 입력
7. 저장
8. 저장 완료와 분석 결과 확인

**현재 마찰**

- 대형 히어로가 작은 화면에서 목표와 CTA를 아래로 밀 수 있다.
- 운동 목록이 길고 상·하위 탭이 겹쳐 탐색 맥락이 복잡하다.
- 입력 모달 필드 오류가 근처에 구체적으로 표시되지 않는다.
- 메모 모달을 배경 클릭으로 닫으면 작성 내용의 의도가 불분명하다.
- 고정 저장 CTA와 모바일 키보드·Safe Area 회귀 가능성이 있다.

**개선 성공 지표**

- 첫 화면에서 목표·추천·기록 CTA 식별
- 즐겨찾기 또는 검색으로 운동 선택 시간 감소
- 저장 가능 조건과 부족한 입력을 필드 가까이 안내
- 저장 성공 후 수정·다음 행동 명확

## J03 홈/일지 → 과거 기록 찾기 → 상세 확인·삭제

**성공 조건:** 날짜 또는 기간·부위 기준으로 기록을 찾고, 위험 동작 전 결과를 이해한다.

1. 하단 `일지`
2. 달력 또는 일·주·월·년 기간 선택
3. 부위 필터
4. 기록 카드 또는 날짜 선택
5. 상세 확인
6. 필요 시 삭제

**현재 마찰**

- 월간 달력과 별도 기간 필터가 동시에 있어 어느 조건이 목록에 적용되는지 학습이 필요하다.
- 삭제는 브라우저 confirm과 화면 메뉴가 혼용된다.
- 삭제 후 실행 취소가 없고, 위험성 표현이 화면마다 다르다.
- 카드 메뉴가 바깥 클릭·Escape·포커스 복귀를 완전히 관리하지 않는다.

**개선 성공 지표**

- 선택 기간과 목록 결과의 관계를 한 문장으로 설명
- 삭제 전 대상과 비가역성 명확화
- 상세 닫기 후 시작 위치로 포커스 복귀

## J04 기록 → 분석 → 다음 운동 결정

**성공 조건:** 분석 기준 기간, 점수 의미, 데이터 부족 정도를 이해하고 다음 운동으로 이동한다.

1. 하단 `분석`
2. 기간 선택
3. 핵심 인사이트 확인
4. 부위 밸런스·근육 순위 확인
5. 추천 루틴 시작 또는 직접 기록

**현재 마찰**

- ‘점’과 비율이 앱 내부 계산값이라는 설명이 접힌 영역에 있다.
- 도넛과 막대가 시각적이지만 스크린리더용 구조화된 요약이 제한적이다.
- 기록 1회와 충분한 기간의 분석 신뢰 차이가 더 명확할 수 있다.

**개선 성공 지표**

- 기간·기록 수·계산 기준을 함께 표시
- 차트 외 텍스트 표로 핵심 값 확인 가능
- 데이터 부족 시 확정적 추천을 피함

## J05 식단 등록 → AI 또는 직접 입력 → 저장

**성공 조건:** 날짜와 식사 구간을 확인하고, AI 추정값을 검토한 뒤 안전하게 저장한다.

1. 하단 `식단`
2. `등록`
3. 날짜·아침/점심/저녁/간식 선택
4. 사진 추가 또는 직접 입력
5. 사진이면 AI 분석 실행
6. 음식명·분량·영양값 검토
7. 저장
8. 요약·달력 반영 확인

**현재 마찰**

- 등록 바텀시트 안에 날짜, 구간, 사진, AI 상태, 음식 편집, 정확도 안내가 모두 나타난다.
- 분석이 최대 1분 걸릴 수 있으나 진행 단계가 단일 문구 중심이다.
- 아침·점심·저녁 덮어쓰기 규칙이 긴 설명에 묻힐 수 있다.
- 숫자 입력 4열은 360px에서 터치·가독성 검증이 필요하다.

**개선 성공 지표**

- 현재 단계와 다음 행동이 항상 하나로 명확
- AI 추정값과 사용자 확정값 구분
- 저장 전 덮어쓰기 규칙 명시
- 실패 시 직접 입력으로 전환 가능

## J06 내 정보 → 목표·신체 정보·즐겨찾기 설정

**성공 조건:** 설정이 어디에 쓰이는지 이해하고 변경값을 저장 또는 취소한다.

1. 하단 `내정보`
2. 개인 정보·주간 목표·개인 루틴 카드 선택
3. 값 변경
4. 저장
5. 홈·운동 기록·식단 목표에 반영 확인

**현재 마찰**

- 신체 정보가 운동 볼륨과 식단 목표에 모두 영향을 준다는 설명이 모달 내부에만 있다.
- 변경 중 배경 클릭 시 저장되지 않은 값이 사라질 수 있다.
- 즐겨찾기 운동 목록은 다시 루틴·하위 탭·검색을 모두 사용한다.

**개선 성공 지표**

- 변경 영향 범위 표시
- 변경 감지 시 저장·계속 편집·버리기 선택
- 선택된 운동 수와 저장 상태 지속 표시

## J07 네트워크 실패 → 복구

**성공 조건:** 데이터 안전 여부와 재시도 방법을 이해한다.

1. 앱 사용 중 오프라인 또는 API 오류
2. 상단 배너·오류 화면 확인
3. 연결 복구
4. 다시 시도
5. 저장 여부 확인

**현재 마찰**

- 오프라인 배너와 로드 오류 배너가 같은 sticky 위치에 동시에 나타날 수 있다.
- 전역 토스트는 3.2초 후 사라져 중요한 저장 실패를 놓칠 수 있다.
- 오프라인 전용 페이지의 재시도는 단순 홈 링크다.

**개선 성공 지표**

- 데이터가 저장됐는지 여부를 명시
- 지속 오류는 사라지지 않는 inline alert로 제공
- 연결 복구 후 동일 행동 재시도 가능
